② 结构守卫重构 零维护

把「结构等价」从「对冻结基线逐条豁免」变成「一个不变量 + 一个金标」。
  • 骨架归一（src/tools/skeleton.py）：把每页的可变槽位（TDK / canonical / hero / seo / faq / JSON-LD / nav / footer / VAR_INIT / aria-pressed / 倒计时 …）换成 {{槽}} 占位，其余结构逐字节保留。
  • 实证：49 种页面结构 → 1 个骨架。此前 49 页各自为政，现在任何一页多出/缺失未声明的结构块会立刻暴露。
  • 结构闸门（src/tools/structure_gate.py）：S1 骨架唯一 / S1a 除首页外都有面包屑 / S2 必需槽位齐全 / S3 金标锁（--update 重签）。
  • 负向测试通过：① 往 index 塞一个 <div class="rogue-panel"> → S1 失败并打印差异行；② 删 typing-tips 的面包屑 → S1a 精确点名。闸门是真会响的，不是装饰。
  • verify.py 400 → 215 行，check 9 从 96 行豁免逻辑变成 9 行委托。以后新增页面/功能，不必再改验证器——这正是旧设计的病根。

③ 外链运维工具化 独立站实操

把「发外链」从一次性体力活，变成可版本化数据 + 可复跑命令。
  • src/tools/directories.json：18 条机器可读台账（名称/URL/类型/dofollow/DR/状态/日期/备注），状态机 candidate→submitted|live|blocked_cf|needs_login|dead|skipped。
  • linkops.py probe：批量探测目录站，自动分类 Cloudflare 墙 / 需登录 / 已下线。只允许「明确信号」改写台账（弱信号"可达"不改，交人工），避免误判污染数据。
  • linkops.py live：sitemap 全量 URL 逐个核实 —— 本次实测 49/49 全 200。
  • linkops.py ledger report：一眼看清 submitted 5 blocked_cf 5 needs_login 5 dead 1 candidate 2。

台账让「Cloudflare 挡住自动化」这件事有据可查，而不是每次凭印象重试——它明确标出 blocked_cf 是「交回人工」而非失败。
