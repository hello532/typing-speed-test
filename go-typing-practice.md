# Go Typing Practice

Source: https://typing.rerivo.com/go-typing-practice.html

Go is deliberately plain, and that is what makes it a good typing drill: short declarations, braces on every line, := and error checks appear so often that they become the rhythm of the language.

Three things. Braces open on the same line as the statement, so almost every line ends with a reach to the right hand. Short declarations (:=) put the colon and equals in sequence, two keys that are not adjacent. And error checks repeat the same three-line idiom constantly, which makes it the single most valuable sequence to automate in your fingers.

The upside is regularity. Once you can type `if err != nil {` without thinking, a large fraction of Go becomes the same motion with different identifiers.

Thirty-six lines of ordinary Go: a package declaration, grouped imports, a struct with a receiver method, an HTTP server start, JSON decoding with the standard error check, context with timeout, a goroutine range loop, a select, slices.SortFunc with a comparison function, sync.WaitGroup, error wrapping with %w, a type switch, a test helper with t.Fatalf, and a mutex with defer.

They are deliberately short. Go lines are short, and the drill should teach the shape of the language rather than test your endurance with a long expression.

Start with the three highest-frequency sequences: `if err != nil {`, `for _, v := range`, and `defer x.Close()`. Type each twenty times slowly, then in a normal round. Automation of those three is worth more than raw speed.

Then add the punctuation that bites: the colon-equals, the ampersand for addresses, and the backtick for struct tags - which needs the key most typists have never used.

## Frequently asked questions

### What typing speed do Go developers have?

No one measures it formally. Most developers type prose at 60-90 WPM and real Go at 45-55, because braces and short declarations add right-hand reaches.

### Why is Go slower to type than Python?

Go is brace-dense and every block closes with a reach, while Python uses indentation. Go also repeats the error-check idiom, which is fast only once it is automatic.

### Is this real Go?

Yes - 36 lines of ordinary Go covering goroutines, channels, context, error wrapping, generics-era slices helpers, struct tags and tests.

### What should I drill first?

`if err != nil {`, `for _, v := range` and `defer ...Close()`. Those three sequences cover a large share of real Go lines.

### How long until I see a gain?

Two weeks of five-minute daily rounds usually shows 4-7 WPM on Go content, mostly from the brace reach and the := sequence becoming automatic.
